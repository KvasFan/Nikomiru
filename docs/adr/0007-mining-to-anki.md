# ADR 0007 — Mining to Anki

| Field | Value |
|---|---|
| Status | Accepted |
| Date | 2026-10-20 |
| Requirements | ANK-001…ANK-006, ANK-010…ANK-013, ANK-020…ANK-027, ANK-030…ANK-039, ANK-050…ANK-053, APP-002, PLY-011, POP-014 (Ctrl+Enter), PRV-001, NFR-SEC-01, NFR-SEC-02, NFR-PERF-08 |
| Milestone | M4 |

## Context

M4 makes a Lapis card from the popup in one click: AnkiConnect, the Lapis note type, the field composer, the sentence audio and image, and the `nikomiru://` link back to the scene. The specification fixes most of it, but before writing the code four readings were compared: the specification itself, Fushi's mining code at commit `ac8034e`, Lapis 1.7.0 and AnkiConnect (releases 25.11.9.0 and 26.10.14.0), and the Nikomiru code at the end of M3. They left open questions (who runs the flow, how mpv reports a screenshot, how the glossary becomes HTML, how media reach a sandboxed Anki, what "session" means for the last card) and a few places where Fushi has defects that should not be copied. This record gives the answers; the specification is updated with it.

## Decision

### Where the code goes

1. **`nikomiru-anki` knows nothing about video** (D-12). It holds the AnkiConnect client, the Lapis note type, the placeholders and the field renderer, the glossary serializer, the media names and the `nikomiru://source` link (build and parse). It depends on `nikomiru-dict` for the entries and the structured content, never on the player or the UI (ARC-010).
2. **The video side of mining** is split as the rest of the app: the session (`nikomiru-ui`) chooses the reference cue (ANK-031), computes the clip (ANK-032) and builds a mining request; a new **`anki` worker thread** in `nikomiru-app` runs it (screenshot, ffmpeg jobs, composition, upload, `addNote`) and answers through the event-loop proxy, like the other workers (SPECIFICATION §5.3). The same thread runs the duplicate checks, the configuration refresh and "Create Lapis deck", one request at a time. Audio and image are made in parallel on two short-lived threads of that worker (ANK-035).
3. **The dictionary part of a card is composed from the raw entry**, not from the popup's view model: the request carries the popup's query and the entry's index; the worker repeats the lookup (an LRU hit) and checks that the entry has the same expression and reading, otherwise the card is refused ("the dictionaries changed"). The view model has lost what Anki needs (the structured-content tags and `data` attributes that Lapis styles, the dictionary CSS, the raw frequencies).

### AnkiConnect

4. **Only the legacy API, version 6**, at `POST <url>/`, on every request and every `multi` child. The JSON-RPC API v1 came with AnkiConnect 26.10.11.0, nine days ago, and needs Anki 26.08 or later; the legacy API stays supported and existing clients keep working. Default URL `http://127.0.0.1:8765`: AnkiConnect listens on IPv4 only, so `localhost` can try `::1` first. HTTPS is accepted in the URL for a reverse proxy the user runs; AnkiConnect itself speaks plain HTTP.
5. **Transport: `reqwest` with the `blocking` and `native-tls` features**, already chosen in SPECIFICATION §4 (no `json` feature: `serde_json` builds the bodies). Proxies are disabled (`no_proxy`, SET-007), idle connections are not kept (`pool_max_idle_per_host(0)`) and every request says `Connection: close`: AnkiConnect closes the socket after each reply without announcing it in 25.11.9.0, which is how Fushi's pooled client reused dead sockets (its BUG-065). Timeouts: 5 s to connect, 10 s per request. The `key` field is sent only when the API key is not empty: an empty key fails against an unset one.
6. **Retries follow the phase that failed** (ANK-003). With no pooled connections there is no expired one to retry; instead:
   - a request that **failed to connect** (refused, connect timeout, TLS) never reached Anki and is retried once, whatever the action;
   - a **read-only or idempotent** action (`version`, `deckNames`, `modelNames`, `modelFieldNames`, `modelNamesAndIds`, `canAddNotesWithErrorDetail`, `findNotes`, `notesInfo`, `getMediaFilesNames`, `storeMediaFile`, `deleteMediaFile`, `createDeck`, `updateNoteFields`, `addTags`, `guiBrowse`) is also retried once when the connection closes before the reply, but not after a reply timeout (Anki is busy: a second wait doubles it);
   - **`addNote` and `createModel`** (and a `multi` holding one) are not retried after the request was sent: the result is "unknown outcome, check in Anki" (`CommitUnknown`), and the media already uploaded are kept.
7. **The tests use a fake AnkiConnect written for them**, not wiremock: a `std::net::TcpListener` server in `nikomiru-anki` behind a `test-support` feature, which answers from a script of replies, records every request and can close a connection before replying or never reply. wiremock cannot drop a connection at a chosen point, and it would bring tokio and an async test runtime into tests whose client is blocking. The L6 tests start the same fake and point `[anki] url` at it. The exit criterion "T-ANK-* green on mocks (wiremock)" reads "on the fake AnkiConnect".

### Lapis

8. **The three files of the upstream tag `1.7.0`** (commit `38238d0b1c072fe7d7cd121e1e4c838a959f8d6b`) are copied byte for byte into `assets/anki/lapis/` (`front.html`, `back.html`, `styling.css`) with a `PROVENANCE.md` (URL, tag, commit, date, SHA-256 of each file, licence, authors, update procedure). A test pins the three SHA-256 values. Fushi's copy is not used: its back template carries two Fushi edits under a "do not hand-edit" header. Nikomiru adds nothing to the files; a change would go in a separate, documented file.
9. **"Create Lapis deck"** creates the note type `Lapis` with one card template named **`Mining`**, the name of the official Lapis package (Fushi says `Card 1`), the 22 fields of ANK-010 and the vendored CSS; then the deck `Lapis` (`createDeck` is idempotent), then refreshes and checks both by name (ANK-011). The outcome is `created` when either one was new. AnkiConnect 26.10 refuses `createModel` while any Anki editor window is open; that error gets its own message ("close Anki's Browse and Add windows").
10. **SelectionText stays unmapped** (ANK-012): Fushi fills it with the popup's selection text, which a video card does not have.

### Fields

11. **Every value that comes from a subtitle, a dictionary, a file name or the user is HTML-escaped** before it enters a field (`&`, `<`, `>`, `"`, `'`). Fushi leaves `{sentence}`, `{document-title}`, the dictionary names and the frequency labels unescaped; a subtitle line with `<` would become markup in Anki's web view, where the Lapis templates run scripts.
12. **`{glossary}` is written like Yomitan's Anki export**, because the Lapis CSS styles that markup (`li[data-dictionary=…]`, `[data-sc-…]`, `ol`, `ul`, `i`): `<div style="text-align: left;" class="yomitan-glossary"><ol>`, one `<li data-dictionary="D"><i>(tags, D)</i> <span>…</span></li>` per sense (ANK-023). Structured content becomes HTML through the same allowlist as the popup (POP-009): only its tags; `data` keys as `data-sc-<key>` attributes with names limited to letters, digits, `-` and `_` (and the non-ASCII letters some dictionaries use); `class="gloss-sc-<tag>"`; inline styles only for the properties and values the CSS subset of DIC-035 accepts, written back from the checked values; links become `<span>`; nothing from the dictionary is copied as markup. The dictionary's `styles.css` and the user's CSS (DIC-035) enter as one `<style>` per dictionary, rewritten from the rules the subset keeps and scoped to `.yomitan-glossary [data-dictionary="D"]`: no `@import`, no `url()`, no selector the subset does not understand, and only the rules whose tags, classes and attributes occur in the glossary (Fushi slims the CSS the same way). `{glossary-first}` and `{single-glossary-<dictionary>}` use the same blocks for one dictionary; `<dictionary>` matches the title, then the name shown on the dictionaries page.
13. **Images inside glossaries are uploaded with the card**, as Fushi does: the bytes come from the dictionary's media (the image types of POP-010, at most 4 MiB each, at most 32 per card), named by content like the other media; a missing image keeps its alternative text.
14. **`{sentence}`** is the reference cue's plain text, escaped, with its lines joined by `<br>`; the looked-up word is wrapped in `<b>` at the click offset when the text there matches the entry, otherwise at its first occurrence, otherwise not at all (ANK-024). Fushi's video path always takes the first occurrence. `{cue-sentence}` is the same as `{sentence}` until ANK-041 (M6) merges cues.
15. **Other placeholders Fushi defines and the specification does not**: `{reading}` is the entry's reading (the headword itself when the dictionary gives none, as in Yomitan); `{pitch-accent-positions}`, `{pitch-accent-categories}` and `{phonetic-transcriptions}` follow Fushi's `popup.js` (its vectors become T-ANK-02x cases); `{document-title}` is the video's file name without extension until series exist (M5); `{tags}` is the entry's term tags, comma-separated; `{audio}` is empty until word audio (M5).
16. **Tags**: the user's tags, then `nikomiru` and `video`, deduplicated in order (ANK-027). The series tag waits for series (M5): a tag made from a file name would differ for every episode.

### Video, media and the link

17. **One interval for audio, link and timestamp**: the padded clip of ANK-032 in video time (delay applied), at most 30 s (a longer clip keeps its first 30 s). `{clip-timestamp}` and the link's `startMs`/`endMs` use it, as in Fushi; reopening the link seeks to the clip start and highlights the first cue that overlaps the clip.
18. **Sentence audio** as ANK-033, with `-map 0:<ff-index>` of the active audio track (Fushi uses the ordinal among audio tracks, which counts differently when a file has several kinds of stream). No audio track, or a failed extraction, cancels the card (ANK-035). The level becomes a setting: `audio_quality_level` 0 = mono 64k (default), 1 = stereo 128k, 2 = stereo 192k.
19. **The image** is the frame on screen: the popup has paused playback (POP-001), so the frame of the click is still the one on screen when the card is made. The player gets **commands with a reply**: they run in order on the `mpv-commands` thread like the others, and their result goes back on a channel; the `anki` worker waits on it, never the UI thread. `screenshot-to-file <cache>/mining/<id>.png video` is the first one, then ffmpeg scales it (never up) and encodes it: JPEG `-q:v` 5 / 3 / 2 for levels 0 / 1 / 2 (about q80 / q90 / q95), WebP `-quality` 80 / 90 / 95, level 3 at the original size. A failed image still makes the card, without a picture (Fushi does the same). The alternative "frame at the start of the cue" is ffmpeg alone (`-ss` before `-i`, one frame) and waits for the advanced mining of M6.
20. **Temporary files** live in `$XDG_CACHE_HOME/nikomiru/mining/` (NFR-SEC-02) and are removed when the attempt ends.
21. **Media names and upload** (ANK-036): `nikomiru_<the first 16 hex digits of the SHA-256 of the bytes>.<ext>`. Media are always uploaded as base64 `data`, never by `path`: Anki opens a `path` itself, and the Flathub Anki cannot read Nikomiru's cache (its manifest grants no file access); the bytes are a few hundred kilobytes. Before uploading, one `multi` of `getMediaFilesNames` tells which names already exist; only the new ones may be deleted again. The name AnkiConnect returns is the one written in the fields. If `addNote` fails with a known error (duplicate, wrong field, missing deck), the new media are deleted; after `CommitUnknown` nothing is deleted. Base64 is a short encoder in `nikomiru-anki` with the RFC 4648 vectors, not a new crate.

### Duplicates, the last card, overwrite

22. **The + / ✓ state** is checked when a popup's content arrives, for all its entries in one `canAddNotesWithErrorDetail`: the first field of the note type rendered from its template (media placeholders empty), `allowDuplicate: false`, `duplicateScope` `deck` with `{"deckName": <deck>, "checkChildren": true, "checkAllModels": true}`, or `collection` with `{"checkChildren": false, "checkAllModels": true}`, the same options `addNote` sends. Only the exact text `cannot create note because it is a duplicate` means ✓. `unsupported action` (AnkiConnect older than 24.2.26.0) falls back to `findNotes`. A transport error stops the checks for 30 s in the whole process; any answer ends the pause. The checks run only when the URL is loopback (`localhost`, `127.0.0.0/8`, `::1`): a remote AnkiConnect is contacted only by an action of the user (PRV-001). While unknown, the button shows +.
23. **"Session" is the run of the app.** ✓↩ marks the last card made since Nikomiru started (its note id is kept in memory) and wins over ✓. Clicking ✓ opens a menu with "Open in Anki" and "Add anyway"; clicking ✓↩ opens the same menu with "Overwrite" first. Overwrite is offered only for that last card (ANK-037): `notesInfo`, refusal if the note type changed, `updateNoteFields` with every field of the note type (unmapped ones `""`), `addTags`, then `notesInfo` again to check that the fields were written (25.11.9.0 can lose the write while the note is open in Anki's browser; 26.10 refuses it with an "editor open" error that gets its own message). `mined_cards` is updated with the new values.
24. **"Open in Anki"** (ANK-038) is `guiBrowse` with `nid:<id>` for a card made in this run; for a word, `findNotes` with Anki's own duplicate search, `dupe:<model id>,<first field>` for each note type (from `modelNamesAndIds`, added to ANK-005) restricted to the deck when the scope is `deck`, so that it finds what made the button show ✓ (the fix of Fushi's BUG-2051).
25. **Anki unreachable**: the card is not made, the toast says why (ANK-004), the media are removed. No pending queue (Fushi queues the card; T-REL-002 asks for the error).

### Storage, configuration, links

26. **`mined_cards`** is a new table of `library.redb`, keyed by note id, postcard records (expression, reading, sentence, video uid, start, end, `source_id`, creation time). A new table does not change the records of the existing ones, so the schema version stays 1 (as for `dictionaries`); changing a record's encoding still needs a migration.
27. **`[anki]` in `config.toml`** (SPECIFICATION §9) gets a typed section, with `audio_quality_level` added and `field_mapping` per note type. The app writes it (Anki settings, "Create Lapis deck") with the existing atomic 0600 save; values out of range are clamped as in `[lookup]`; the API key never appears in a log or an error.
28. **`nikomiru://source` links** are recognised before a target is turned into a path (today a link would become a junk record of the library): the strict parser of ANK-051, with Fushi's rules for the values (integers without sign or leading zeros up to 2³¹−1, a lowercase UUID, `startMs ≤ endMs`, a uid without `/` at the start, drive letters, `file:`, `..`, backslashes or control characters, at most 1024 characters), `v=1`, `kind=video`, `ep` (`0` until series exist). Unknown uid or missing file: a message with "Locate the file", which opens the portal's file chooser and saves the new path in the video's record.
29. **`assets/nikomiru.desktop`** (APP-002) with `Exec=nikomiru %U`, `MimeType=x-scheme-handler/nikomiru;` and the video types of LIB-001; `cargo xtask install` puts the binary in `~/.local/bin` and the file in `~/.local/share/applications` and registers the scheme with `xdg-mime`, for builds from source until the packages of 1.0.
30. **PLY-011**: `S` saves a PNG of the frame without subtitles as `$XDG_PICTURES_DIR/Nikomiru/<file name> <HH-MM-SS.mmm>.png` through the same command with a reply, and a toast names the file. It belongs to M4 (the shortcut table said M1).
31. **Ctrl+Enter** makes the card of the entry the keyboard is on (POP-014) in the topmost popup; a new action of the popup context.

## Consequences

- The HTTP stack enters the build: reqwest, hyper, tokio (inside reqwest's blocking client, one thread), `url` and `idna`, whose `icu_properties` and `icu_properties_data` are Unicode-3.0 (class B `icu_*`, SPECIFICATION §3.2); their `deny.toml` exceptions come back. Building needs the OpenSSL development files.
- The specification changes in the same pull request: ANK-001 (one URL, loopback), ANK-003 (retry by phase), ANK-005 (`modelNamesAndIds`), ANK-010 (upstream tag, `Mining`), ANK-021/023/024 (escaping, the serializer, the sentence), ANK-027 (no series tag before M5), ANK-030/037 (session, menu), ANK-033 (quality level), ANK-036 (always `data`, existing files), ANK-038 (`dupe:`), §5.3 (the `anki` worker, commands with a reply), the shortcut table (PLY-011 in M4, Ctrl+Enter), §8 (`mined_cards`), §9 (`audio_quality_level`).
- The test plan follows: the fake AnkiConnect for T-ANK-001…003, T-ANK-011, T-ANK-030, T-ANK-036, T-ANK-037; rows for the requirements that had none (ANK-004, 005, 006, 010, 020, 031, 038, 039, 053).
- Lapis keeps its credit notices and its licence (GPL-3.0, the same text as Nikomiru's `LICENSE`); `THIRD_PARTY_LICENSES.html` lists crates only, so the README and the About screen credit Lapis.
- Not built here: the pending queue, word audio, animated covers and video clips, the advanced mining dialog, merged cues, the AnkiDroid back end, an AnkiConnect installer (Anki and AnkiConnect stay external programs, TEST §3).
