# 2.180.0: an Android preview, manga on more pages, 2026-11-21

Base: `v2.174.1`. The maintainer asked for the GitHub page brought up to date, manga reading and display improved by comparing more pages of Kaiji and Nana, installation files for Android, Windows and Linux, and a release on GitHub (D-84).

## Manga: four sets of pages

The real app with the real models (`l7_a_real_manga_is_read_ahead`, release build), measured with the same script as for 2.174.1 and every changed block compared side by side with the original. Two volumes not looked at before were added, so that nothing is tuned to one book.

| Set | Blocks | Size / original line width, median / 10th percentile | Uncovered ink, median / 90th percentile | Blocks changed by 2.180.0 |
|---|---|---|---|---|
| Kaiji volume 1, pages 5–24 | 253 | 1.00 / 0.85 | 0.011 / 0.335 | 0 |
| Kaiji volume 7, pages 40–69 | 223 | 1.00 / 0.91 | 0.005 / 0.308 | 2 |
| Nana volume 1, pages 10–39 | 356 | 1.00 / 0.87 | 0.034 / 0.308 | 3 |
| Nana volume 11, pages 60–89 | 232 | 1.00 / 0.79 | 0.031 / 0.280 | 5 |

- The ten changed blocks were looked at one by one ([AK-BUG-010](../bugs/AK-BUG-010.md)): columns no longer run up into a balloon's outline or a frame (都合10人 on Kaiji 7 p.44 now starts where the picture has it; on Nana 11 p.67 the black band of the frame is no longer whitened, which the script counts as more uncovered ink). No block got worse to the eye.
- Two digits in a column (10 in 都合10人) are written side by side in one cell, as the picture does.
- A rule that also stopped a column at ink reaching in from one side was tried and dropped: it changed 46 blocks of Nana, where columns stand close, and spoiled a column of ー.
- **Still open**: the reader's own misreadings (かな read as カムー on Nana 11 p.82, a drawn sound effect read as ああ… on Nana 11 p.60), これで on Kaiji 7 p.44 a little high (art beside it), one size per balloon.

## Android

On an Android 15 emulator (x86_64, Google's default image, SwiftShader GLES 3), with the APK of `cargo xtask android` (`--debug` for `run-as`):

| Check | Result |
|---|---|
| Install, start | The setup assistant, then the library; Japanese text drawn with Android's fonts. |
| Add a folder | Android's "all files access" given (by `appops` on the emulator); the app's chooser lists `/storage/emulated/0`, enters `Movies`, and **Use this folder** adds it; the library finds the video. |
| Play | `av_basic.mkv` plays through mpv's render API on GLES 3 (libmpv-android 1.1.0, mpv 0.42), audio through AAudio, with its Japanese subtitles in the list. |
| Background and back | Home, then the app again: the surface is made again and the video goes on. |
| Phone upright | The pages drawn at 560 points across, the bar kept above Android's navigation bar; the player's bar is crowded upright. |
| arm64 | The arm64-v8a library links; its segments and libmpv's are aligned to 16 KiB. |

Found and fixed on the way: android-activity's `set_window_flags` stalls the app when called while the event loop runs (the screen is now kept on through Java's main thread); a chooser opened from a page stayed behind it; mpv's VA-API interop option is refused on Android.

## Final regression

`cargo xtask ci --full` (with `ANDROID_HOME` set, so the new Android step ran): **all green**, with **145 actual GUI cases passed** in 386 seconds.
