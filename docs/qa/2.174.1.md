# 2.174.1: manga text at the original's size, two columns read apart, 2026-11-19

Base: `v2.174.0`. The maintainer reported, in Kaiji volume 1, letters still too small, columns not read and a wrong transcription now and then ([AK-BUG-009](../bugs/AK-BUG-009.md)).

## How it was checked

The same runs as for 2.173.1, in the real app with the real models (`l7_a_real_manga_is_read_ahead`), measured with the same script (now sizing as the app does), each block compared with the 2.173.1 run, and the pages seen side by side.

## Results

| | 2.173.1 | 2.174.1 |
|---|---|---|
| Kaiji 5–24: characters' size / original line width, median / 10th percentile | 0.95 / 0.77 | 1.00 / 0.85 |
| Kaiji 5–24: uncovered ink, median / 90th percentile | 0.011 / 0.344 | 0.011 / 0.335 |
| Kaiji 5–24: blocks that gained a line | — | 4 (ベンツじゃ read whole, three …！ columns) |
| Nana 10–39: characters' size / original line width, median / 10th percentile | 0.93 / 0.77 | 1.00 / 0.87 |
| Nana 10–39: uncovered ink, median / 90th percentile | 0.034 / 0.308 | 0.034 / 0.308 |
| Nana 10–39: blocks whose lines changed | — | 0 |

- The 90th percentile of the size in Kaiji (1.57) is the text's size against columns of dots, narrower than the characters beside them.
- **Still open**: the reader sometimes reads ．．．！ as dots only, and misreads a character now and then: the OCR model's own errors, not the layout's.

## Final regression

`cargo xtask ci --full`: **all green in 541 seconds**, with **145 actual GUI cases passed**.
